# Daily Green プロダクト定義書

## 1. プロダクト概要

Daily Green は、ログイン済みユーザーが毎日の習慣を管理し、その達成状況を GitHub の contribution graph のような Activity Log で振り返るための習慣管理アプリである。MVP では、毎日繰り返す習慣をシンプルに扱い、「その日に達成した事実だけを記録する」ことを基本ルールとする。

### ターゲットユーザー

- 物事を後回しにしがちな人
- 習慣化アプリが続かなかった人
- 日々の積み上げを視覚的に確認したい人

## 2. MVP の前提

### 認証

- 利用にはログインが必須
- ゲスト利用は提供しない

### 習慣の基本ルール

- 習慣は毎日繰り返す
- 習慣自体に終了期限は設けない
- 今日の対象習慣は、そのユーザーの「アーカイブされていない全習慣」とする
- アーカイブ済みの習慣はホーム画面に表示しない
- アーカイブ済み習慣の一覧画面は MVP では提供しない

### 日付と期限

- 1 日の区切りと期限は **JST（Asia/Tokyo）固定** とし、各日付の締めは **翌日 00:00 JST**（当日 24:00 と同義）で判定する
- クライアントのローカル時刻には依存せず、すべての日付変更・期限判定はサーバー側のタイムスタンプを基準に行う
- `daily_record.date` を含む日付値の解釈、日付変更、期限判定、Activity Log の日次集計はすべて JST 基準で扱う
- 習慣ごとの個別期限は MVP では設けない
- 期限後の達成は存在しない
- 締め時刻である翌日 `00:00 JST` までに達成していない習慣は、その日の未達成として扱う
- 実装メモ: 現行の Drizzle スキーマでは `habit.deadTime` が必須カラムとして残っているが、MVP では全習慣で締め時刻を **翌日 00:00 JST**（当日 24:00 と同義）として扱い、個別期限の意味では利用しない。スキーマは後続のマイグレーションで追従する前提とする

## 3. 用語定義

| 用語 | 定義 |
| --- | --- |
| 今日の対象習慣 | その日時点でアーカイブされていない習慣。ホーム画面に表示される当日の習慣群。 |
| 達成記録 | 習慣を当日中に達成したときだけ作成される記録。DB 上では `daily_record` に保存する。 |
| Activity Log | GitHub の contribution graph と同じ発想で日ごとの達成率を可視化するログ。 |
| ストリーク | 連続して達成が続いている日数。 |
| アーカイブ | 習慣を現在の対象習慣から外す状態。ホーム画面には表示しない。 |

## 4. 機能仕様

### 4.1 習慣の達成ルール

- 各習慣は毎日 1 回達成対象になる
- 当日中（締め時刻である翌日 `00:00 JST` まで）に達成操作が行われた場合のみ、その日の達成として扱う
- 期限後に達成へ変更する操作は提供しない
- `Done(遅延)` のような遅延達成の概念は持たない
- 未達成日は「記録がない」ことで表現し、未達成専用のレコードは作成しない

### 4.2 `daily_record` の扱い

- `daily_record` は達成時のみ作成する
- 未達成時は `daily_record` を作成しない
- 1 つの習慣に対して、同じ日付の達成記録は 1 件までとする
- `daily_record.date` は、その習慣を達成した日付を表す
- 実装メモ: 現行の Drizzle スキーマでは `daily_record.status` が必須だが、MVP では未達成レコードを持たない運用を正とし、状態カラムを不要にする方向で後続のスキーマ変更を行う

### 4.3 ストリーク

- 習慣を達成したタイミングで `currentStreak` を増やす
- その時点で必要に応じて `maxStreak` を更新する
- 未達成によるストリークのリセットは、定期バッチでは行わない
- ホーム画面のデータ取得前に、そのユーザーのストリーク補正を毎回実行する
- ホーム画面には、補正後の `currentStreak` を表示する

### 4.4 ホーム画面

ホーム画面は、当日の達成状況を確認し、そのまま習慣を完了できる画面とする。

- 画面上部に Activity Log を表示する
- 「今日の習慣」セクションに、そのユーザーの対象習慣を表示する
- 習慣カードの並び順はタスク名順とする
- 完了済みカードは再操作不可とする
- 完了済みカードには完了状態が分かる見た目を適用する
- 対象習慣が 0 件のときは「タスクがない」と表示する
- タスク追加ボタンは「今日の習慣」の右側に配置する
- 前日以前の未達成カードを持ち越して並べる仕様にはしない
- 日付が変わると、その日の対象習慣からなる初期カード群を表示する

### 4.5 Activity Log

Activity Log は、1 日単位の達成率を色で表現する。

- 表示の考え方は GitHub の contribution graph と同じとする
- 色の種類・配色は GitHub の contribution graph に合わせる
- ただし色の決定ルールは、Daily Green 独自に「その日の達成率」で決める
- 各日付の達成率は、その日が終わる翌日 `00:00 JST` 時点で確定する
- 達成率は `その日に達成した習慣数 / その日が終わる翌日 00:00 JST 時点の対象習慣数` とする
- その日に達成した習慣数は、その日付の `daily_record` 件数で求める
- 分母となる対象習慣数は、その日が終わる翌日 `00:00 JST` 時点の値で固定する
- 後から習慣をアーカイブしても、過去日の達成率と色は変わらない

## 5. 画面上の挙動まとめ

- ログイン後にホーム画面へ遷移する
- 当日の対象習慣のみが表示される
- 習慣を達成すると当日の `daily_record` が作成され、カードは完了状態になる
- 締め時刻である翌日 `00:00 JST` を過ぎた未達成の習慣は、その日の達成対象から外れ、翌日は新しい 1 日として扱う
