# Daily Green プロダクト定義書

## 1. プロダクト概要

Daily Green は、ログイン済みユーザーが毎日の習慣を管理し、その達成状況を GitHub の contribution graph のような Activity Log で振り返るための習慣管理アプリである。MVP では、毎日繰り返す習慣をシンプルに扱い、「その日に達成した事実だけを記録する」ことを基本ルールとする。

### ターゲットユーザー

- 物事を後回しにしがちな人
- 習慣化アプリが続かなかった人
- 日々の積み上げを視覚的に確認したい人

## 2. MVP の前提

### 認証

- 利用にはログインが必須
- ゲスト利用は提供しない

### 習慣の基本ルール

- 習慣は毎日繰り返す
- 習慣自体に終了期限は設けない
- 今日の対象習慣は、そのユーザーの「アーカイブされていない全習慣」とする
- アーカイブ済みの習慣はホーム画面に表示しない
- アーカイブ済み習慣の一覧画面は MVP では提供しない
- active habit（`archivedAt IS NULL`）はユーザーあたり最大 10 件とする
- アーカイブ済みを含む habit の総数はユーザーあたり最大 1000 件とする
- いずれかの上限を超える習慣作成は受け付けず、`409 Conflict`（`HABIT_LIMIT_EXCEEDED`）とする

### 日付と期限

- 1 日の区切りと期限は **JST（Asia/Tokyo）固定** とし、各日付の締めは **翌日 00:00 JST**（当日 24:00 と同義）で判定する
- クライアントのローカル時刻には依存せず、すべての日付変更・期限判定はサーバー側のタイムスタンプを基準に行う
- `daily_record.date` を含む日付値の解釈、日付変更、期限判定、Activity Log の日次集計はすべて JST 基準で扱う
- `timestamptz` は特定タイムゾーンのローカル日時ではなく絶対時刻として保存する。JST の日付境界判定と API レスポンスの `+09:00` への変換はアプリケーション側で行う
- 習慣ごとの個別期限は MVP では設けない
- 期限後の達成は存在しない
- 締め時刻である翌日 `00:00 JST` までに達成していない習慣は、その日の未達成として扱う
- 実装メモ: MVP では全習慣で締め時刻を **翌日 00:00 JST**（当日 24:00 と同義）として扱う

## 3. 用語定義

| 用語 | 定義 |
| --- | --- |
| 今日の対象習慣 | その日時点でアーカイブされていない習慣。ホーム画面に表示される当日の習慣群。 |
| 達成記録 | 習慣を当日中に達成したときだけ作成される記録。DB 上では `daily_record` に保存する。 |
| Activity Log | GitHub の contribution graph と同じ発想で日ごとの達成率を可視化するログ。 |
| ストリーク | 連続して達成が続いている日数。 |
| アーカイブ | 習慣を現在の対象習慣から外す状態。ホーム画面には表示しない。 |

## 4. 機能仕様

### 4.1 習慣の達成ルール

- 各習慣は毎日 1 回達成対象になる
- 当日中（締め時刻である翌日 `00:00 JST` より前）に達成操作が行われた場合のみ、その日の達成として扱う
- 期限後に達成へ変更する操作は提供しない
- `Done(遅延)` のような遅延達成の概念は持たない
- 未達成日は「記録がない」ことで表現し、未達成専用のレコードは作成しない
- アーカイブ済み習慣への達成操作は `HABIT_ARCHIVED` で失敗する
- 同じ習慣に対する archive と complete は共通の排他機構で直列化し、先に成立した処理を優先する
- archive が先に成立した場合、後続の complete は `HABIT_ARCHIVED` で失敗し、`daily_record` を作成しない
- complete が先に成立した場合、`daily_record` の作成と `currentStreak` / `maxStreak` の更新を完了した後、後続の archive が成立する

### 4.2 `daily_record` の扱い

- `daily_record` は達成時のみ作成する
- 未達成時は `daily_record` を作成しない
- 1 つの習慣に対して、同じ日付の達成記録は 1 件までとする
- `daily_record.date` は、その習慣を達成した日付を表す
- `daily_record.date` の日付境界は JST の半開区間 `[D 00:00 JST, D+1日 00:00 JST)` で扱い、ちょうど `00:00 JST` の達成は新しい日の記録とする
- 実装メモ: 現行の Drizzle スキーマでは `daily_record.status` が必須だが、MVP では未達成レコードを持たない運用を正とし、状態カラムを不要にする方向で後続のスキーマ変更を行う

### 4.3 ストリーク

- 習慣を達成したタイミングで `currentStreak` を増やす
- その時点で必要に応じて `maxStreak` を更新する
- 未達成によるストリークのリセットは、定期バッチでは行わない
- ホーム画面のデータ取得前に、そのユーザーのストリークの期限切れ判定を毎回実行する
- この Lazy Update は、期限切れの `currentStreak` を `0` にリセットする処理だけを指す。`daily_record` 全履歴からストリークを完全再計算する処理ではない
- `currentStreak > 0` であり、直近達成日が `null` または「昨日」より前の場合をリセット対象とする
- Lazy Update に失敗した場合は補正前の値でホーム画面を返さず、リクエスト全体をエラーとする
- ホーム画面には、補正後の `currentStreak` を表示する

### 4.4 ホーム画面

ホーム画面は、当日の達成状況を確認し、そのまま習慣を完了できる画面とする。

- 画面上部に Activity Log を表示する
- 「今日の習慣」セクションに、そのユーザーの対象習慣を表示する
- 習慣カードの並び順は `name` 昇順、同名の場合は `createdAt` 昇順、さらに同一の場合は `id` 昇順とする
- 完了済みカードは再操作不可とする
- 完了済みカードには完了状態が分かる見た目を適用する
- 対象習慣が 0 件のときは「タスクがない」と表示する
- タスク追加ボタンは「今日の習慣」の右側に配置する
- 前日以前の未達成カードを持ち越して並べる仕様にはしない
- 日付が変わると、その日の対象習慣からなる初期カード群を表示する

### 4.5 Activity Log

Activity Log は、1 日単位の達成率を色で表現する。

- 表示の考え方は GitHub の contribution graph と同じとする
- 色は GitHub の contribution graph 風の緑色の濃淡とする
- ただし色の決定ルールは、Daily Green 独自に「その日の達成率」で決める
- 日付 D の達成記録の受付は、D が終わる D+1日 `00:00 JST` で締め切る。過去日の `completionRate` 自体は表示時点の active habit を使って再集計するため、後日の archive によって変わり得る
- 当日分の Activity Log エントリを表示する場合、`completionRate` はその日の確定前であるため `null` とし、翌日 `00:00 JST` 到達後に確定値へ置き換える
- Activity Log は表示時点で active（`archivedAt IS NULL`）な習慣だけを全日付の計算対象とする
- 日付 D の対象習慣は、`createdAt < D+1日 00:00 JST` かつ `archivedAt IS NULL` を満たす habit とする
- 分子は、日付 D の対象習慣に属する `daily_record` のうち `date = D` の件数とする
- 分母は、日付 D の対象習慣数とする
- アーカイブ済み習慣は、アーカイブ日時にかかわらず過去日の分子・分母からも除外する。このため、archive 後に過去日の達成率と色が変わることを許容する
- 過去日で対象習慣数が `0` の場合も `completionRate: null` とする。当日未確定の `null` と同じ値で表し、MVP の UI では理由を区別しない
- `null` は未確定または対象なし、`0` は達成なしとして、それぞれ緑の達成レベルとは別の色で表示する
- 正の達成率は GitHub contribution graph 風の緑 4 段階へマッピングする。`0 < completionRate <= 0.25` を level 1、`0.25 < completionRate <= 0.50` を level 2、`0.50 < completionRate < 1.00` を level 3、`completionRate === 1.00` を level 4 とし、レベルが高いほど濃い緑とする

## 5. 画面上の挙動まとめ

- ログイン後にホーム画面へ遷移する
- 当日の対象習慣のみが表示される
- 習慣を達成すると当日の `daily_record` が作成され、カードは完了状態になる
- 締め時刻である翌日 `00:00 JST` を過ぎた未達成の習慣は、その日の達成対象から外れ、翌日は新しい 1 日として扱う

## 6. 今後の検討事項

- アーカイブ済み習慣を閲覧・復元する UI をいつ追加するか
- Activity Log やストリークを使ったシェア機能の詳細
- 通知機能を導入する場合のタイミングと導線
- シェアリンクとプッシュ通知は将来拡張であり、`share_link` / `push_subscription` テーブルを含めて MVP 実装対象外とする
