# コーディング規約

## テスト

### テストケース名

プロジェクトメンバーは主に日本語話者であるため、テストケース名は原則として日本語で記述する。

- `describe` は、対象の関数名・クラス名・モジュール名を表すため、英語の識別子をそのまま使ってよい
- `it` / `test` は、何を保証するテストなのかを日本語で記述する
- 技術用語、関数名、HTTP method、エラーコードなどは無理に翻訳しない
- 既存コードとの整合性や外部ライブラリの慣例上、日本語にすると不自然な場合は英語でもよい

例:

```ts
describe("handleApiRequest", () => {
	it("未認証リクエストでは統一形式の 401 レスポンスを返す", async () => {
		// ...
	});

	it("認証済みユーザーの handler 結果を JSON レスポンスとして返す", async () => {
		// ...
	});

	it("ApiError 例外を統一形式の JSON レスポンスに変換する", async () => {
		// ...
	});
});
```

避けたい例:

```ts
it("maps authenticated handler results to JSON responses", async () => {
	// ...
});
```

この規約は、テスト失敗時の出力や PR レビュー時に、仕様として何を確認しているかを読み取りやすくするためのもの。
